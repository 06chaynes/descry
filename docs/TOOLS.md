# Tool reference

Generated by `tools/docs/gen_tools.py` from the MCP server's tools,
`CONTRACT.md` and the CLI; do not edit. The examples are answers
from `tests/ground_truth/python`. Rules, failures and the entries an
answer lists are in `CONTRACT.md`.

A name two definitions share is refused with the choices:

```json
{
  "error": "'parse' names 2 definitions; give one by node ID:\n  - FILE:app/io.py::Reader::parse\n  - FILE:app/models.py::Order::parse",
  "reason": "ambiguous",
  "choices": [
    "FILE:app/io.py::Reader::parse",
    "FILE:app/models.py::Order::parse"
  ]
}
```

## health

Quick health check for debugging. Returns server version, graph status, and feature availability (SCIP, embeddings). Use to verify MCP connection and diagnose issues. Related: descry_status, descry_ensure.

No parameters.

Answer: `status`, `version`, `project_root`, `cache_dir`, `warm`, `max_depth` (the deepest a `flow` or `context` goes), `features`, `graph`

MCP `descry_health`; web `GET /api/health`; CLI `usage: descry health [--json]`

## ensure

Ensure the codebase graph exists and is fresh. Call this FIRST before other descry queries. Regenerates if missing or older than max_age_hours (default: the project's configured max_stale_hours). Returns graph status with node/edge counts. WARNING: May take 30-60 seconds if regeneration is needed.

| parameter | type | default |
|---|---|---|
| `max_age_hours` | number | null |

Answer: `action` (`ready`, `refreshed`, `generated`), `summary`, `graph` (status)

MCP `descry_ensure`; web `POST /api/ensure`; CLI `usage: descry ensure [--json] [--max-age-hours MAX_AGE_HOURS]`

Check if the codebase graph exists and its freshness. Returns existence, age, and node/edge counts.

## context

Get full context for a symbol: source code, callers, callees, tests (~500+ tokens). Use brief=true (~50 tokens) to quickly verify a symbol before fetching full context. Options: full=true (no truncation), expand_callees=true (inline dependencies), head_lines=N (preview first N lines). symbol takes a node ID or a symbol name.

| parameter | type | default |
|---|---|---|
| `symbol` | string | required |
| `brief` | boolean | false |
| `full` | boolean | false |
| `expand_callees` | boolean | false |
| `deduplicate` | boolean | false |
| `depth` | integer | 1 |
| `max_tokens` | integer | 2000 |
| `callee_budget` | integer | 2000 |
| `head_lines` | integer | null |
| `max_output_tokens` | integer | null |

Answer: `symbol` (definition), `brief`; brief: `callers`, `callees` (counts); else `depth`, `callers`, `callees` (references), `callers_more`, `callees_more` (counts), `examples` (`file`, `line`, `candidates`), `members` (`id`, `name`, `line`, `tokens`), `tests`, `configs` (`id`, `line`, `type`), `omitted`, `truncated`; with `deduplicate`, a symbol shown before answers `symbol` and `repeated` only

MCP `descry_context`; web `GET /api/context`; CLI `usage: descry context [--json] [--brief] [--full] [--expand-callees] [--deduplicate] [--depth DEPTH] [--max-tokens MAX_TOKENS] [--callee-budget CALLEE_BUDGET] [--head-lines HEAD_LINES] [--max-output-tokens MAX_OUTPUT_TOKENS] symbol`

Direction 'forward' traces callees (what this calls), 'backward' traces callers (what calls this). depth is the levels of calls below the start, at most the project's [query] max_depth (default 3).

| parameter | type | default |
|---|---|---|
| `start` | string | required |
| `direction` | `forward` or `backward` | "forward" |
| `depth` | integer | 3 |
| `target` | string | null |
| `inline_threshold` | integer | 100 |

Answer: `start`, `direction`, `asked`, `depth`, `target`, `root` (tree: `id`, `name`, `type`, `tokens`, `file`, `line`, `kind`, `candidates`, `children`, `more`, `more_possible`, `seen`), `path_to_target`?, `cut`?

## search

Search symbol names and docstrings. Returns compact single-line results by default. After finding candidates, use descry_context with brief=true to verify relevance, then fetch full context only for confirmed-relevant symbols. Set compact=false only when you need signatures and docstrings inline. Combines keyword + semantic search. Use filters for specific crates/languages.

| parameter | type | default |
|---|---|---|
| `terms` | array | required |
| `compact` | boolean | true |
| `limit` | integer | 10 |
| `lang` | `all` or `c` or `cpp` or `cs` or `csharp` or `dart` or `go` or `java` or `javascript` or `js` or `kotlin` or `php` or `protobuf` or `py` or `python` or `rb` or `rs` or `ruby` or `rust` or `scala` or `svelte` or `ts` or `typescript` or `vbnet` | null |
| `crate` | string | null |
| `type` | `function` or `class` or `method` or `constant` or `file` or `all` | null |
| `exclude_tests` | boolean | false |

Answer: `method` (`keyword`, `hybrid`), `query`, `total`, `results` (definitions)

MCP `descry_search`; web `GET /api/search`; CLI `usage: descry search [--json] [--compact | --no-compact] [--limit LIMIT] [--lang LANG] [--crate CRATE] [--type {function,class,method,constant,file,all}] [--exclude-tests] terms [terms ...]`

| parameter | type | default |

Set full=true to see complete source without truncation. Set brief=true for minimal output (~50 tokens) - just signature, location, counts.

| parameter | type | default |
|---|---|---|
| `symbol` | string | required |
| `full` | boolean | false |
| `brief` | boolean | false |

## churn

Find code churn hotspots - symbols or files that change most often. Use for identifying unstable code, refactoring targets, or areas that need better test coverage. Mode 'symbols' (default) maps changes to functions/methods via the graph, 'files' shows file-level stats, 'co-change' shows symbol pairs that frequently change together.

| parameter | type | default |
|---|---|---|
| `time_range` | string | null |
| `path_filter` | string | null |
| `limit` | integer | 20 |
| `mode` | `symbols` or `files` or `co-change` | "symbols" |
| `exclude_generated` | boolean | true |

Answer: `mode`, `time_range`, `path_filter`, `truncation_note`?, and `symbols`, `files`, `pairs` (with `file_level`?) or `message`

MCP `descry_churn`; web `GET /api/churn`; CLI `usage: descry churn [--json] [--time-range TIME_RANGE] [--path-filter PATH_FILTER] [--limit LIMIT] [--mode {symbols,files,co-change}] [--include-generated]`

## evolution

Track how a specific symbol has changed over time. Shows commit timeline with authors and change sizes. Counts the symbol's own lines, not those of definitions inside it, followed across renames and line drift as churn follows them. Set show_diff=true to include actual diff hunks.

| parameter | type | default |
|---|---|---|
| `symbol` | string | required |
| `time_range` | string | null |
| `limit` | integer | 10 |
| `show_diff` | boolean | false |
| `crate` | string | null |

Answer: `node_id`, `mode` (`lines`, `file`), `truncation_note`?, `authors`, `commits` (`hash`, `date`, and in `lines` mode `added`, `removed`); or `message`

MCP `descry_evolution`; web `GET /api/evolution`; CLI `usage: descry evolution [--json] [--time-range TIME_RANGE] [--limit LIMIT] [--show-diff] [--crate CRATE] symbol`

## changes

Analyze change impact for a commit range. Maps changed lines to symbols and shows their callers for ripple-risk assessment. Use for code review, understanding what a set of commits affected, or pre-merge impact analysis. Defaults to HEAD~1..HEAD if no range specified.

| parameter | type | default |
|---|---|---|
| `commit_range` | string | null |
| `time_range` | string | null |
| `path_filter` | string | null |
| `show_callers` | boolean | true |
| `limit` | integer | 50 |

Answer: `range`, `commits`, `files_count`, `symbols_count`, and `symbols` (with `callers`) or `changed_files`; or `message`

MCP `descry_changes`; web `GET /api/changes`; CLI `usage: descry changes [--json] [--commit-range COMMIT_RANGE] [--time-range TIME_RANGE] [--path-filter PATH_FILTER] [--show-callers | --no-show-callers] [--limit LIMIT]`
